# 高级规格化复审结论权威设计

日期：2026-08-08

## 背景

导入期规格化提供低、中、高三档思考深度。中档对语义候选执行一次 LLM 判断；高档在初判建议改变内容或归属时执行第二次复审，并且当前实现只有两轮结论一致才允许修改。

这一规则只能撤销初判提出的修改，不能纠正初判遗漏：

- 初判为 `keep` 时不会触发复审，因此第二轮没有机会发现本应执行的规格化操作；
- 初判与复审不一致时一律保留原文，即使复审已经结合原始候选和初判理由给出了更可靠的替代结论；
- 无编号章节归属和普通段落续接的第二次调用当前没有收到初判内容，不能把第一次的判断依据作为辅助证据；
- 页边界噪声与跨页表格虽已向复审提供初判，但最终仍要求两轮一致。

这会让高档比中档保留更多尚未规格化的内容，而不是让第二次判断修正第一次判断。

## 已确认决策

- 中档行为不变，使用一次有效初判的结论。
- 高档对每个具有有效初判的语义候选执行一次复审，包括初判为 `keep` 的候选。
- 复审请求包含原始固定候选、相同上下文和完整初判结果；初判只是辅助证据。
- 复审返回完整替代结论。复审有效时，以复审的 action、confidence、reason 和角色判断为最终 LLM 结论，不要求与初判一致。
- 复审无效、低置信度、调用失败或输出校验失败时，回退使用有效初判结论。
- 初判无效时保留原文，不执行没有可靠辅助输入的复审。
- 无论最终采用复审还是初判，既有确定性结构校验、候选绑定、内容守恒和无数据丢失规则仍是最终安全权威。
- 高档每个候选或页边界批次最多执行两次 provider 调用：一次初判、一次复审。为保证有效初判后一定有复审额度，高档的每个逻辑轮次不使用格式校验重试；中档现有调用与校验行为不在本次范围内。

## 目标

1. 让高级思考模式能够同时纠正初判的假阳性和假阴性。
2. 让所有规格化类型使用一致的“复审优先、无效回退初判”语义。
3. 让第二次 LLM 明确看到第一次的完整结论，但仍独立输出完整替代判断。
4. 保持导入期规格化所有权、原始 IR 只读和确定性安全边界不变。
5. 保持初判与复审均可审计，不丢失两轮证据。

## 非目标

- 不改变低档和中档的产品语义。
- 不改变候选生成、结构 veto、置信度阈值、列映射或内容守恒算法。
- 不让 LLM 绕过确定性安全校验。
- 不在 compare 阶段新增任何规格化或表格合并。
- 不迁移已经导入的历史文档；用户需重新导入才能获得新行为。
- 不抽象通用的跨领域两阶段决策框架。

## 设计

### 统一决策顺序

每个候选的高档决策遵循以下顺序：

1. 执行初判，并使用现有严格 schema、候选 ID、枚举、类型、置信度和理由校验。
2. 初判无效时，最终保持原文并结束该候选。
3. 初判有效时，无论 action 是否为 `keep`，都执行复审。
4. 复审使用相同的严格输出校验。
5. 复审有效时，将复审判断作为最终 LLM 判断。
6. 复审无效时，将初判作为最终 LLM 判断。
7. 将最终 LLM 判断交给既有确定性安全校验；只有同时满足结构约束的操作才能修改规格化副本。

该顺序区分两类权威：LLM 两轮之间由有效复审优先，LLM 与确定性规则之间始终由确定性规则优先。

### 调用预算

高档需要为两个逻辑轮次各保留一次调用额度：

- 初判调用无效时，不把第二次调用当作初判格式重试，也不再复审；候选保持原文；
- 初判调用有效时，第二次调用固定用于复审；
- 复审调用无效时不重试，直接回退初判；
- 因此每个候选或页边界批次最多两次 provider 调用。

中档不进入复审编排，本次不改变其现有调用和校验策略。

### 复审输入和提示词

每个复审入口显式接收对应的初判对象，并在用户消息中增加类型明确的 `initial_judgment` 或 `initial_labels`：

- 页边界噪声：完整批次标签列表；
- 无编号章节归属：action、confidence、reason；
- 普通段落续接：action、confidence、reason；
- 跨页表格：continuation role、row action、table action、confidence、reason。

复审 system message 明确说明：

- 初判仅作为辅助证据，不是必须确认的答案；
- 必须针对相同固定候选重新评估；
- 必须返回完整、可独立校验的替代结论；
- 有效复审将成为最终 LLM 结论；
- 不得改写、生成、替换或重新绑定候选内容。

### 显式复审入口

保持各领域输出结构独立，不引入通用动态类型框架：

- 页边界噪声继续使用 `review_page_noise_batch()`；
- 为章节归属增加显式复审入口，复用相同响应解析器；
- 为段落续接增加显式复审入口，复用相同响应解析器；
- 跨页表格继续使用 `review_continuation()`。

初判函数只负责第一次判断，复审函数负责构造带初判证据的第二次请求。pipeline 负责选择“有效复审，否则有效初判”的最终 LLM 判断。

## 各规格化类型的数据流

### 页边界噪声

高档对每个有有效初判的边界批次执行复审，即使初判全部为 `keep`。最终标签列表整体取有效复审，否则取初判。连续边缘删除规则只检查最终标签，不再计算初判与复审是否一致，也不再生成 `page_noise_review_disagreement`。

最终标签提出删除时，仍须满足既有高置信度、固定 ID、顺序完整和边缘连续性要求。

### 无编号章节归属

高档在初判为 `keep` 或 `move_to_section` 时都执行章节复审。复审有效时直接替换初判；无效时回退初判。不再生成 `section_parent_review_disagreement`。

最终 `move_to_section` 仍只能指向请求中固定的前一章节，并继续受既有候选生成与响应绑定校验约束。

### 普通段落续接

高档在初判为 `keep` 或 `merge_paragraphs` 时都执行段落复审。复审有效时直接替换初判；无效时回退初判。不再生成 `paragraph_merge_review_disagreement`。

最终 `merge_paragraphs` 仍只能合并固定 previous/continuation 槽位，并继续执行页关系、标题边界、文本连接、sentence 投影和内容守恒校验。

### 跨页表格续接

高档在初判的 row action 和 table action 均为 keep 时也执行复审。有效复审完整替换初判的角色、行操作、表片段操作、置信度和理由；不再逐字段要求两轮一致，也不再取两轮最低置信度。

重复表头删除资格只根据最终 LLM 判断中的 continuation role 确认，但仍必须满足已接受的 fragment 合并、等价保留表头和既有确定性安全条件。行合并、fragment 合并、列映射和结构 veto 均继续由现有规则约束。

## Trace 与可观测性

- 保留 initial judgment 和 review judgment 的原始有效结果。
- 最终 decision/operation 记录实际采用的结论和理由。
- 有效复审被采用时，最终理由以复审理由为准；不再拼接成“两轮一致”的理由。
- 复审失败时记录稳定的 review failure code，并让最终 decision 明确来源为 initial fallback。
- 删除 disagreement 类型的拒绝原因，因为两轮不同不再构成拒绝。
- 现有调用计数继续区分 initial、review、成功、失败和跳过。

## 错误处理

- provider 不可用：保持现有无 LLM 修改行为。
- 初判异常、非法 JSON、字段不完整、候选绑定错误或低置信度：保留原文，不复审。
- 复审异常、非法 JSON、字段不完整、候选绑定错误或低置信度：使用有效初判。
- 最终 LLM 结论触发结构 veto、不可投影、内容不守恒或来源歧义：保留原文，并记录现有确定性拒绝原因。
- 一个候选失败不阻止后续独立候选处理。

## 测试策略

### 共享行为

- 中档仍使用一次判断，不触发复审。
- 高档初判有效时，无论初判 action 是否修改，都恰好执行一次复审。
- 高档最多两次 provider 调用。
- 复审 prompt 包含完整初判并声明其为辅助证据。
- 初判无效时保持原文且不复审。
- 复审无效、低置信度、调用失败或绑定错误时使用初判结论。

### 纠错矩阵

四类规格化分别覆盖：

1. 初判 `keep`、复审建议修改：在确定性校验通过时应用修改。
2. 初判建议修改、复审 `keep`：保留原文。
3. 初判与复审给出不同修改维度：使用复审的完整结论。
4. 两轮结论相同：行为与当前成功路径等价。
5. 复审无效：使用初判，包括初判修改可在确定性校验通过后生效。
6. 最终 LLM 建议修改但确定性校验失败：仍保留原文。

### 回归范围

- `tests/test_structure_repair_llm.py`：页边界噪声、章节归属、段落续接；
- `tests/test_normalization.py`：三档深度及导入管线集成；
- 表格规格化相关单元测试：row/table action、角色和 trace；
- UI/graph/service 的 depth 传递测试保持现有枚举和持久化值不变。

## 验收标准

1. 高档不会因初判为 `keep` 而跳过复审。
2. 有效复审能够推翻初判并成为最终 LLM 结论。
3. 复审无效时采用有效初判，而不是无条件保留原文。
4. 初判与复审不一致本身不再产生拒绝。
5. 所有既有确定性安全规则仍能阻止不安全修改。
6. 中档、低档、UI 枚举、导入所有权和 compare 只读边界不变。
7. trace 能同时还原初判、复审、最终采用来源及确定性拒绝原因。
