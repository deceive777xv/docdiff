# 跨页表格重建与中置信度 LLM 裁决设计

## 背景

当前 PDF 解析结果会将连续 Markdown 表格行保存为一个 `Paragraph`，并在对比阶段将表格拆成行级单元。对于同一业务表格跨页、同一行又被分页截断的文档，解析结果中可能同时出现：

- 前一片段最后一行只包含单元格前半段；
- 后一片段第一条正文行的关键列为空，只保留续接内容；
- 页面边界处存在比正文表格更宽的页眉表格；
- 页眉表格与正文表格被抽取到同一个宽网格中；
- 两个文档版本在不同业务行处分页。

现有 `DocumentIR` 不保存页码、坐标或原始表格 ID。本功能必须只依据已有 JSON 中的章节顺序、段落顺序、表格行、空单元格和两个版本之间的对应内容完成重建，不能依赖原始 PDF，也不能硬编码页眉文案、业务列名或固定列号。

## 目标

1. 在语义匹配前重建被分页切开的业务表格及表格行。
2. 识别并排除夹在表格片段中的重复宽表页眉，避免产生虚假差异。
3. 自动处理结构证据充分的高置信度候选。
4. 对中置信度候选调用 LLM 做受约束的二元裁决，提高总体准确率。
5. 保持原始解析 JSON 不变，并使对比页面能够重放本次任务使用的完全相同的重建结果。
6. 保存可追溯的结构证据、LLM 判断和最终操作，便于定位误判。

## 非目标

- 不修改 PDF 解析器或重新解析原始 PDF。
- 不写回或覆盖原始 `DocumentIR` JSON。
- 不重建 Chunk、FAISS 索引或数据库中的历史数据。
- 不迁移历史对比任务，也不保证历史任务获得跨页表格重建效果。
- 不在第一版增加设置页、人工确认界面或用户可调阈值。
- LLM 不得生成、改写、概括或补全任何单元格内容。

## 方案选择

采用“对比前只读规范化”方案。重建发生在章节对齐之后、表格行匹配之前，输入为两个已经对齐的章节，输出为规范化后的 `SectionPair` 及任务级 `ReconstructionTrace`。

相比直接重写 JSON，该方案不需要迁移已有解析结果、重建索引或处理旧段落 ID。相比只在 `semantic_matcher` 中临时修改匹配文本，独立重建层可以让匹配、分类和页面展示共享同一份结构决策。

## 总体数据流

```text
加载两个原始 JSON
  -> align_sections
  -> reconstruct_table_pairs
       -> 规则发现候选
       -> 高置信度自动决策
       -> 中置信度 LLM 裁决
       -> 应用确定性转换
       -> 生成 ReconstructionTrace
  -> match_paragraphs
  -> classify
  -> 持久化差异结果和 ReconstructionTrace
```

对比工作流增加 `do_reconstruct_tables` 节点，位于 `do_align` 和 `do_semantic_compare` 之间。`compare_service.py` 的同步执行路径调用同一个公开入口，不能复制另一套规则。

对比页面不重新执行候选发现或 LLM 调用。页面加载两个原始 JSON 后，只读取当前任务的 `ReconstructionTrace` 并重放其中已经确定的操作。

## 组件边界

### 表格结构模型

重建模块定义仅供对比链路使用的内部模型：

- `SourceRowRef`：原始文档侧、`section_id`、`paragraph_id` 和 sentence 索引。
- `TableRowMatrix`：保留全部空单元格的原始行及其归一化视图。
- `TableFragment`：一个表格段落及其在章节中的顺序、行区域和有效列。
- `ColumnProfile`：列的非空率、值类型、长度分布和重复度。
- `ContinuationCandidate`：固定的前一行、疑似续行、后一行、列映射及证据。
- `ReconstructionDecision`：规则等级、LLM 裁决和最终操作。
- `ReconstructionTrace`：文档哈希、算法版本和全部决策。

这些模型不改变 `app/core/types.py` 的持久化 `DocumentIR` 契约。规范化段落使用从来源引用和操作类型计算出的确定性派生 ID。

### 重建模块

新增独立模块负责：

1. 解析 Markdown 表格行并保留空单元格；
2. 将宽表按占位模式划分为页眉区域、正文数据区域和稀疏续行区域；
3. 推断不同片段之间的正文列映射；
4. 识别页面边界噪声；
5. 生成续行候选及结构证据；
6. 对中置信度候选调用 LLM；
7. 在 `SectionPair` 的深拷贝上应用已接受的转换；
8. 生成和重放任务级 trace。

普通段落和未参与重建的表格行保持原始顺序与原始文本。

## 表格结构识别

### 行矩阵解析

Markdown 行只移除最外侧的一对 `|`，内部连续分隔符产生的空单元格必须保留。结构分析使用去除 Markdown 强调标记和 HTML 换行标签后的归一化文本，但最终合并始终使用未经改写的原始单元格文本。

分隔行、全空行和普通内容行必须分别标记，不能在结构分析开始前直接丢弃。

### 行区域划分

一个表格段落可能同时包含宽表页眉和正文表格。重建器按照以下变化将行划分为连续区域：

- 单元格总数变化；
- 非空列占位向量变化；
- 分隔行出现；
- 列值类型分布突变；
- 多行稳定正文模式开始或结束。

区域分类依赖统计特征组合，不能依赖文档标识标签、页码标记等任何固定源文本。

### 正文列推断

对每个候选正文区域建立列画像：

- 非空比例；
- 数字、层级编号、短标签、长文本和占位符比例；
- 文本长度分布；
- 在相邻行中的稳定性；
- 与同章节其他片段及另一个版本中各列的内容类型相似度。

不同宽度片段通过保持列顺序的单调映射对齐。映射评分由列画像相似度、正文行共同出现模式、关键值连续性和跨版本内容支持组成。没有映射到正文逻辑列的原始列可以标记为边界表格列。

实现不得固定使用样例中出现的任何原始列索引。样例中的正文列映射仅作为验收结果，不作为规则输入。

### 边界噪声识别

区域只有在多项证据同时成立时才会被标记为边界噪声：

- 在多个表格片段的开头或结尾重复出现；
- 占位模式与正文数据区域不兼容；
- 缺少正文关键列的连续性；
- 相同或近似文本在多个单元格中异常重复；
- 附近存在分隔行或占位模式突变。

内容重复本身不是充分条件。具有稳定正文列模式和关键值位置的真实重复数据行必须保留。

位于两个兼容正文片段之间的短普通段落，只有在章节内重复出现且位置稳定时才可视为边界附属内容；否则它会阻断跨片段合并。

## 续行候选生成

只检查相邻逻辑片段的交界处。移除已确认的边界噪声后，候选固定为：

- 前一片段最后一条正文数据行；
- 下一片段第一条疑似续行；
- 下一片段随后第一条完整正文行。

候选必须满足以下前置条件：

1. 两个片段的正文逻辑列可以兼容映射；
2. 疑似续行是下一片段的第一条正文行；
3. 疑似续行至少有一个正文内容列非空；
4. 两个片段之间不存在未被识别为边界附属内容的普通正文或新章节。

以下情况属于硬否决，不得调用 LLM：

- 疑似续行已经包含明确的新关键值或新序号；
- 疑似续行是分隔行、表头或重复边界区域；
- 前后片段列模式无法兼容映射；
- 交界处出现新章节或明确的新表结构；
- 候选需要跨过一条真实正文数据行才能合并；
- 合并会覆盖两个同时非空且明显冲突的关键单元格。

## 结构置信度

通过前置条件的候选按支持证据数量和冲突情况分为三档。支持证据包括：

1. 疑似续行的关键列为空；
2. 随后的完整行恢复与前一片段一致的关键值类型或序列模式；
3. 前一行与疑似续行在同一内容列形成互补；
4. 前一单元格结尾与续行开头具有文本连续性；
5. 两个片段之间只包含重复边界内容；
6. 另一个文档版本存在对应完整行或不同分页位置产生的互证。

分档规则为：

- 高置信度：前置条件全部满足、无硬否决或显著冲突，并至少具有四项支持证据；自动合并。
- 中置信度：前置条件全部满足、无硬否决，并具有两到三项支持证据；提交 LLM 裁决。
- 低置信度：支持证据不超过一项，或存在非硬性的明显冲突；保持分离。

文本连续性只能作为一项证据，不能单独触发合并。序号连续性不是必需条件，因此非序号型表格仍可通过其他证据进入高或中置信度。

## LLM 裁决

每个中置信度候选单独调用一次现有模型 provider。单次调用只包含：

- 固定候选 ID；
- 前一行、疑似续行和后一条完整行的逻辑单元格数组；
- 推断出的列角色和列映射摘要；
- 规则层的支持与冲突证据；
- 另一个版本对应位置的有限邻域行。

不得传入整篇文档，也不得要求模型选择任意行。模型只回答当前固定候选是否为续行。

输出必须是严格 JSON：

```json
{
  "candidate_id": "stable-id",
  "decision": "merge",
  "confidence": 0.91,
  "reason": "候选行关键列为空，正文列与上一行语义连续，另一个版本存在对应完整内容"
}
```

校验要求：

- `candidate_id` 必须与请求一致；
- `decision` 只能是 `merge` 或 `keep_separate`；
- `confidence` 必须是 `0.0` 到 `1.0` 的数值；
- `reason` 必须是非空字符串；
- 响应中不得包含替换后的单元格内容或额外操作。

只有 `decision=merge` 且 `confidence >= 0.75` 时才接受合并。其他合法响应保持分离。解析失败、超时、provider 异常或置信度不足时，仅放弃当前候选，不使整个对比任务失败。

LLM 不能推翻任何硬否决，也不能改变列映射、选择其他来源行或生成文本。实际逐列合并完全由确定性代码执行。

## 转换语义

接受合并后，重建器按逻辑列逐列处理：

- 续行单元格为空时保留前一行原值；
- 前一单元格为空时采用续行原值；
- 两者均非空且属于内容列时，按原始顺序直接连接，并只补充防止词语粘连所需的最小换行标记；
- 两者均非空且属于关键列时不得合并；
- 被吸收的续行不再作为独立匹配单元；
- 重复边界区域不进入规范化正文表格，也不参与差异匹配。

完成行级决策后，采用同一逻辑列映射的相邻正文片段合并成一个规范化表格 `Paragraph`。规范化表格只保留第一组被识别为正文表头的标题行和分隔行；后续重复表头、宽表边界区域以及已确认的边界附属短段落从规范化对比副本中移除。原始 `DocumentIR` 中的这些内容不受影响。

如果两个片段只能完成列投影但不满足逻辑表连续性，则分别生成规范化表格，不能仅因列数相同而合成一个整体。

所有转换必须是幂等的：对已经应用同一 trace 的规范化结果再次重放，不得重复拼接内容。

## 决策持久化与重放

每个新对比任务保存：

```text
exports/<task_id>.reconstruction.json
```

sidecar 至少包含：

```json
{
  "schema_version": 1,
  "algorithm_version": "cross-page-table-v1",
  "baseline": {"doc_id": "baseline-document", "file_hash": "baseline-sha256"},
  "target": {"doc_id": "target-document", "file_hash": "target-sha256"},
  "decisions": [
    {
      "candidate_id": "candidate-baseline-001",
      "side": "baseline",
      "source_rows": [
        {"section_id": "section-a", "paragraph_id": "paragraph-a", "sentence_index": 5},
        {"section_id": "section-a", "paragraph_id": "paragraph-b", "sentence_index": 3}
      ],
      "column_mapping": {"0": 0, "1": 1, "2": 2, "4": 3},
      "rule_confidence": "medium",
      "rule_evidence": ["blank_key_cells", "compatible_column_profile", "cross_version_support"],
      "llm": {
        "model": "configured-provider-model",
        "decision": "merge",
        "confidence": 0.91,
        "reason": "续行关键列为空，正文列与上一行连续，另一个版本存在对应完整行"
      },
      "final_action": "merge",
      "generated_row_id": "reconstructed-row-001"
    }
  ],
  "operations": [
    {
      "operation_id": "operation-001",
      "side": "baseline",
      "type": "project_columns",
      "source_rows": [
        {"section_id": "section-a", "paragraph_id": "paragraph-b", "sentence_index": 4}
      ],
      "column_mapping": {"0": 0, "1": 1, "2": 2, "4": 3}
    },
    {
      "operation_id": "operation-002",
      "side": "baseline",
      "type": "drop_boundary_rows",
      "source_rows": [
        {"section_id": "section-a", "paragraph_id": "paragraph-b", "sentence_index": 0}
      ]
    },
    {
      "operation_id": "operation-003",
      "side": "baseline",
      "type": "merge_rows",
      "decision_id": "candidate-baseline-001",
      "source_rows": [
        {"section_id": "section-a", "paragraph_id": "paragraph-a", "sentence_index": 5},
        {"section_id": "section-a", "paragraph_id": "paragraph-b", "sentence_index": 3}
      ],
      "generated_row_id": "reconstructed-row-001"
    },
    {
      "operation_id": "operation-004",
      "side": "baseline",
      "type": "merge_fragments",
      "source_paragraph_ids": ["paragraph-a", "paragraph-b"],
      "generated_paragraph_id": "reconstructed-table-001"
    }
  ]
}
```

`decisions` 记录为什么接受或拒绝候选，`operations` 记录页面需要按顺序重放的全部实际转换。列投影、边界行或边界附属段落过滤、续行合并和表格片段合并都必须形成显式 operation；页面不得根据 decision 临时重新推导操作。未产生实际转换的 `keep_separate` 决策只进入 `decisions`。

主差异结果 JSON 的现有列表格式保持不变。任务重新运行时覆盖同名 sidecar。

页面重放前必须校验 `schema_version`、两侧 `doc_id` 和 `file_hash`。sidecar 内容损坏、版本不支持或哈希不匹配时不应用任何部分转换，并记录警告。缺少 sidecar 时按原始 JSON 展示只作为防崩溃兜底，不属于历史任务兼容或专项验收范围。

差异结果与 sidecar 应先写入临时文件，再原子替换正式文件。只有两个文件均成功落盘后，任务才可标记为 `completed`。LLM 单个候选失败不会使任务失败，但 sidecar 持久化失败必须使任务失败，避免结果和页面结构不一致。

## 页面展示

对比页面加载已完成的新任务时：

1. 加载两侧原始 `DocumentIR`；
2. 加载并校验任务级 sidecar；
3. 只重放 trace 中的确定性列投影、边界过滤和续行合并；
4. 使用规范化后的段落和派生 ID 渲染双栏；
5. 沿用现有差异 ID 聚焦和同步滚动行为。

页面不得再次调用 LLM 或重新计算置信度。这样同一任务的差异匹配文本与后续展示始终一致。

## 测试策略

### 单元测试

覆盖：

- Markdown 行解析完整保留空单元格；
- 不同宽度表格的数据区域识别；
- 正文有效列的顺序映射；
- 重复宽表页眉与真实重复数据行的区分；
- 序号型与非序号型表格的续行候选；
- 新表头、新表格和合法空关键列行触发硬否决或保持分离；
- 高、中、低结构置信度分流；
- 高置信度不调用 LLM；
- 中置信度处理 LLM 同意、拒绝、低置信度、超时和无效 JSON；
- LLM 不能绕过硬否决；
- 逐列合并保留原始文本且满足幂等性；
- 原始 `DocumentIR` 始终不变；
- sidecar 序列化、哈希校验和重放一致。

### 集成测试

覆盖：

- 仅一侧跨页；
- 两侧在不同业务行处跨页；
- 两侧在同一业务行处跨页；
- 表格片段之间夹有重复宽表页眉和普通短段落；
- 交界处实际开始新表；
- 重建后仍正确识别新增、删减、数值变化和正文修改；
- graph 与同步 service 路径产生一致 trace；
- sidecar 写入失败时任务不会标记为完成；
- 页面重放后的文本与差异项文本一致，聚焦 ID 仍可用。

### 外部样例验收

用户提供的两份外部 JSON 用于本地端到端验收，但不作为仓库测试的路径依赖。仓库内提交经过脱敏和最小化的结构回归样本。

验收要求：

1. 根据统计结构推断后续宽表中的正文逻辑列，不固定使用样例列号。
2. 排除重复宽表页眉，不将其报告为业务差异。
3. 正确拼接完全虚构的中性拆分示例“cedar pre”与“lude-complete”。
4. 正确重建两个版本中发生在不同分页位置的指定业务行。
5. 不为文档末尾没有后续片段的不完整行虚构内容。
6. 重建后仍保留真实数值变化、目标版本新增行和正文内容变化。
7. 对比页面展示的规范化行与实际差异匹配所用文本一致。

功能完成必须同时满足：

1. 所有新增单元、集成和 UI 测试通过；
