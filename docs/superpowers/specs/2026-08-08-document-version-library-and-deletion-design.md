# 文档版本独立展示与完整删除设计

## 背景

当前文档库以 `documents` 为行粒度：每份文档只显示一行，版本列仅展示最新版本和版本总数。无论用户实际想删除哪个版本，页面上的“删除”都会调用文档级删除，移除该文档及其全部版本。因此，通过“新增版本”导入的版本无法被单独选择或删除。

删除逻辑还有一处数据生命周期缺口。`document_versions.parsed_json_path` 只记录规格化结果 `parsed/<artifact_id>.json`，但一次导入规格化会生成五个具有相同 `artifact_id` 的文件。现有删除只移除数据库记录、FAISS 目录和 `parsed_json_path` 指向的结果文件，遗留 raw IR、结构修复轨迹、规格化轨迹和边界画像。

本设计把文档库调整为版本级列表，并让数据库记录、检索数据和全部规格化产物共享同一个版本生命周期。

## 已确认的产品行为

- 文档库展示数据库中的所有文档和所有版本，每个版本占一行。
- 同一文档的不同版本可以分别选中、分别删除。
- 删除一个仍有兄弟版本的版本时，只删除所选版本及其关联数据。
- 删除文档的最后一个版本时，同时删除已经空置的 `documents` 主记录。
- 不提供“一键删除整份文档及全部版本”的主操作，降低误删风险。
- 数据库中没有版本的空文档仍要显示，可为其新增版本或直接删除空文档。
- 删除版本时，必须一并删除该次规格化产生的全部文件，不能只删除规格化结果 JSON。

## 方案选择

### 采用：版本级扁平列表

每个版本独占一行，同一文档的名称和类型可以在多行重复。选中行即可操作该版本，交互语义最直接，也最符合“不同版本单独控制”的目标。

### 未采用：文档行展开版本

该方案保留文档分组，但用户必须先展开才能看到和操作版本，还要处理展开状态、空文档行及嵌套选择，增加了不必要的交互和测试复杂度。

### 未采用：文档与版本主从双栏

左侧选择文档、右侧管理版本的层级最清晰，但会占用更多页面空间并显著扩大 UI 改动。本次需求只需要完整可见和独立控制，不需要新的主从导航结构。

## 页面设计

文档库表格调整为以下列：

1. 文档名称；
2. 类型；
3. 版本；
4. 状态；
5. 导入时间。

每个有版本的文档按 `version_no` 降序显示版本行；文档之间仍按文档创建时间降序排列。版本显示沿用 `v<version_no>`，存在 `version_label` 时显示为 `v<version_no>（<label>）`。状态使用固定映射：`active` 显示“有效”、`archived` 显示“已归档”、`needs_review` 显示“需复核”。本次只展示状态，不新增状态编辑入口；遇到数据库约束之外的未知值时原样显示，不能阻止文档库加载。

每行保存两个独立的内部标识：

- `document_id`：供“新增版本”使用；
- `version_id`：供版本删除使用，有版本的行必须存在。

空文档显示一行“暂无版本”，其 `document_id` 有值、`version_id` 为空。选择空文档时，“新增版本”可用，删除按钮显示“删除文档”；选择版本行时，删除按钮显示“删除版本”。导入任务运行期间继续禁用新增与删除操作。

页面状态栏继续显示“共 N 份文档，M 个版本”，其中 N 按主记录计数、M 按版本行计数。

## 查询边界

在 `document_repo` 增加面向文档库的联合查询，使用 `documents LEFT JOIN document_versions` 一次返回全部文档和版本。不能先查询文档再逐份调用 `list_versions`，避免文档数量增加后出现 N+1 查询。

联合查询结果至少包含：

- 文档 ID、名称、类型和文档创建时间；
- 版本 ID、编号、标签、状态和版本创建时间；
- 没有版本的文档，其版本字段为 `NULL`。

该查询只服务版本级展示，不改变 compare 页面和 QA 页面现有的版本查询及“最新版本”语义。

## 规格化产物清单

一次 `prepare_import_ir()` 会按 DocumentIR 的 `doc_id` 生成以下文件：

```text
parsed/<artifact_id>.json
parsed/raw/<artifact_id>.json
parsed/traces/<artifact_id>.structure.json
parsed/traces/<artifact_id>.normalization.json
parsed/profiles/<artifact_id>.boundary.json
```

其中 `parsed/<artifact_id>.json` 是数据库保存的 `parsed_json_path`。其余路径均可以从同一 `artifact_id` 确定性推导。

路径推导和删除规则应由导入规格化存储模块提供，而不是在 UI 或仓储层复制字符串拼接。新增一个窄接口，根据 `data_dir` 与 `parsed_json_path` 返回该版本的完整产物清单，并执行精确文件清理。

安全约束：

- 只接受位于当前 `data_dir/parsed` 根下、文件名为普通 `<artifact_id>.json` 的规格化结果路径；
- 路径解析后必须再次验证仍位于预期根目录；
- 只逐个 `unlink` 已知的五个文件，禁止递归删除 `parsed/raw`、`parsed/traces` 或 `parsed/profiles`；
- 文件不存在视为已清理，保证重复调用安全；
- 不使用模糊匹配或目录通配符，不能影响其他版本。

本次不为原始导入文件新增版本级路径字段。`docs/` 中源文件的版本级生命周期需要独立的数据模型变更，不与规格化产物清理混合。

## 版本删除流程

在 `document_repo` 增加单版本删除入口。输入为 `version_id` 和可选 `data_dir`，流程如下：

1. 查询版本记录并取得 `document_id`、`parsed_json_path`；版本不存在时返回明确的未找到结果，不误删其他数据。
2. 在修改数据库前构造并验证该版本的规格化产物清单。
3. 查找基准版本或目标版本引用该版本的 compare tasks。
4. 在同一数据库事务中删除这些任务的 diff items、compare tasks、该版本的 chunks 和版本记录。
5. 若该文档已没有其他版本，在同一事务中删除空置的文档主记录。
6. 数据库事务提交后，删除该版本的 FAISS 目录和五个规格化产物文件。

数据库先提交，避免文件删除成功但数据库回滚后留下仍指向缺失文件的有效版本。文件系统无法与 SQLite 原子提交；若个别文件因权限等原因删除失败，版本删除仍视为数据库操作成功，UI 必须用警告提示残留路径，不能显示为整个删除失败。后续重复清理必须安全。

现有文档级删除入口继续保留为内部兼容能力，但改为枚举该文档的每个版本并复用同一套关联记录和产物清理规则，防止两条删除路径再次漂移。文档库页面不直接暴露批量删除全部版本的按钮。

## 删除确认与错误反馈

选择普通版本行时，确认框明确显示文档名称和版本，例如：

```text
删除《合同》v2 将同时删除该版本的规格化产物、向量索引和关联对比记录，且不可恢复。
```

如果这是最后一个版本，确认框额外说明“该文档记录也会一并删除”。选择空文档时，确认框只说明删除空文档记录。

用户取消时不执行任何数据库或文件操作。删除成功后刷新表格并保留正确的文档、版本计数；文件清理部分失败时显示“版本记录已删除，但以下本地文件未能清理”的警告和精确路径。

## 数据不变量

- 删除一个版本不会修改或重新编号兄弟版本。
- 新版本编号继续沿用现有“当前最大版本号加一”的规则。
- 任何版本删除后，不再存在引用它的 chunks、compare tasks 或 diff items。
- 只有在版本数变为零时才删除文档主记录。
- 规格化产物以版本的 `parsed_json_path` 为删除依据，不以 `documents.id`、`document_versions.id` 或显示名称猜测文件名。
- compare、QA、导入规格化和文档比较算法不因文档库展示改造而改变。

## 非目标

- 不新增版本重命名、状态编辑、归档或恢复操作。
- 不新增批量选择或批量删除。
- 不改变 compare 和 QA 页面默认使用版本的规则。
- 不修改规格化算法、产物内容或产物目录结构。
- 不在本次引入每个版本的原始源文件路径与哈希字段。
- 不迁移或重写已有版本编号。

## 测试策略

### 仓储查询

- 一个文档三个版本时返回三行，版本按降序排列。
- 多个文档按文档创建时间排序，每份文档内部按版本号排序。
- 空文档仍返回一行，版本字段为 `NULL`。

### 单版本删除

- 删除中间版本时保留文档主记录和兄弟版本，不重新编号。
- 删除最后一个版本时同步删除文档主记录。
- 只删除引用所选版本的 chunks、compare tasks 和 diff items，保留兄弟版本的数据。
- 版本不存在时不更改数据库和文件系统。

### 规格化产物清理

- 创建完整的五文件夹具，删除版本后五个文件全部不存在。
- 缺少任意部分文件时仍可重复、安全完成删除。
- 同目录下其他 `artifact_id` 的文件全部保留。
- 非法或越出 `data_dir/parsed` 的路径被拒绝，不删除外部文件。
- FAISS 目录只删除所选 `version_id` 对应目录。
- 模拟单个文件删除失败时，数据库删除完成并返回可供 UI 展示的残留路径。

### 文档库 UI

- 同一文档的多个版本分别显示为独立行，行内 ID 正确。
- 状态栏分别统计文档数和版本数，不把版本行数当作文档数。
- 选择版本行可新增兄弟版本，也可删除当前版本。
- 普通版本和最后一个版本显示不同的确认说明。
- 选择空文档时可新增版本或删除空文档。
- 用户取消确认时不调用删除入口。
- 导入进行中删除与新增按钮保持禁用。

### 回归验证

- 运行 `tests/test_db/test_document_repo.py`。
- 运行 `tests/ui/test_library_page.py`。
- 运行 ingest、compare、QA 相关测试。
- 运行完整测试套件。
- 运行 `git diff --check` 和 Python compile 检查。

## 验收标准

1. 文档库展示全部文档和全部版本，每个版本可独立选中。
2. 删除一个版本不会删除其兄弟版本或文档主记录。
3. 删除最后一个版本会删除空文档主记录。
4. 删除版本会清理该版本全部五个规格化产物、chunks、FAISS 索引和关联对比数据。
5. 清理使用精确路径清单，不能通过递归目录删除影响其他版本。
6. 空文档仍可见且可新增版本或删除。
7. 文档数与版本数统计准确。
8. compare、QA、导入和规格化算法行为保持不变。
