# 内容等价调和与残余段落覆盖设计

## 背景

当前段落匹配以章节对齐后的 paragraph 为候选，已经支持同一作用域内、顺序一致且规范化文本完全相等的相邻窗口匹配。例如，基准侧相邻的 `A`、`B` 在规范化后恰好等于目标侧 `C` 时，可以生成 `2:1` 的 `ParagraphPair`。

仍有三类解析差异会产生伪新增或伪删减：

1. 唯一短文本在两侧属于不同 `section_path`，现有未匹配调和只允许短文本在相同路径内配对。
2. 相同内容在一侧是 paragraph、另一侧是 section title，标题不进入 paragraph 候选。
3. `A旧 + B` 在另一侧被解析为一个长段 `C = A新 + B`。由于 `A旧 + B` 与 `C` 不再精确相等，精确窗口不能建立 `2:1` 匹配；普通匹配可能先把 `A旧` 配给 `C`，随后把仍未匹配的 `B` 报为删减。

本设计在现有主匹配之后增加一个确定性、只读的“内容等价调和”阶段。它不修改导入 IR，不重新执行规范化，也不改变表格匹配所有权。

## 目标

- 唯一短文本可以跨 `section_path` 精确配对。
- paragraph 与 section title 承载相同内容时视为同一内容，不产生新增、删减或格式变化。
- 已匹配长段覆盖相邻未匹配短段时，只分类长段中真正变化的残余内容。
- 章节改名不再仅因原始 `section_path` 字符串不同而阻断正文调和。
- 所有歧义、投影失败和冲突都失败关闭，保留原差异。

## 非目标

- 本次不新增“章节标题修改”差异类型。
- 不根据另一份文档反向修改或重新保存导入 IR。
- 不处理表格单元、跨页表格或表头。
- 不用普通包含关系创建新的主语义匹配。
- 不为非相邻内容执行任意多段重排或全局片段搜索。
- 不增加新的 LLM 调用。

## 已确认的产品行为

- 一侧正文与另一侧章节标题文本相同时，视为相同内容并静默调和。
- 章节名称变化只作为匹配上下文；本次不单独报告标题变化。
- `A旧 + B` 与 `A新 + B` 的准确结果是只报告 `A旧 -> A新`，不能再报告 `B` 新增或删减。
- 中间包含可以处理，但必须证明被移除的短段是唯一、精确且无损投影的保留内容。

## 总体数据流

```text
SectionPair 对齐
  -> 现有 paragraph / sentence-window / table-row 主匹配
  -> 现有精确相邻窗口优先消费
  -> 构建只读内容索引和消费账本
  -> 短文本跨路径精确调和
  -> paragraph 与 section title 角色调和
  -> 已匹配长段的残余短段覆盖调和
  -> 输出最终 ParagraphPair
  -> 现有差异分类和持久化
```

现有 `_exact_adjacent_window_matches` 继续是顺序一致、全文精确相等场景的第一处理层。新阶段只检查它未消费的结果，不重复建立同一个窗口。

## 只读内容索引

匹配器基于传入的 `SectionPair` 和主匹配结果，为两侧构建内部索引。索引项至少包含：

- `side`：baseline 或 target；
- `role`：paragraph 或 section_title；
- `normalized_text`：与 `_normalize_match_text` 一致的规范化文本；
- `document_order`：该内容在原文中的稳定顺序；
- `scope_id`：由当前 `SectionPair`/父作用域产生的请求内标识，不直接使用标题字符串作为身份；
- `section_path`、`section_level` 和父作用域；
- paragraph 或 section 的只读来源引用；
- `consumed`：请求内消费状态。

`scope_id` 只在本次 compare 请求中使用，不持久化，也不伪造跨文档稳定 ID。章节标题轻微变化但仍被 `align_sections` 配对时，两侧正文共享同一个作用域身份；严重改名导致章节没有对齐时，仍只能依靠后续全文唯一证据，不能把标题相似度当作章节身份的唯一证明。

唯一性统计必须覆盖两侧全文的 paragraph 和 section title，包括已经被主匹配消费的内容。不能只统计当前未匹配项，否则重复文本中的其他出现被主匹配消费后，剩余出现会被错误当成“唯一”。

## 消费账本

内容调和维护请求内消费账本：

- 一个 paragraph 最多参与一个最终 `ParagraphPair` 或一个静默标题覆盖；
- 一个 section title 最多覆盖对侧一个 paragraph；
- 现有精确窗口已经消费的来源不能再次参与；
- 残余短段覆盖只能附着到一个已经存在的主匹配；
- 任意候选争用同一来源时，相关候选全部保持原状。

账本不写入 DocumentIR，不改变 paragraph ID、section ID 或持久化 JSON。

## 第一层：唯一短文本跨路径调和

对主匹配后仍然单侧存在的普通、完整、非表格 paragraph：

1. 使用现有段首列表标记和空白规范化规则。
2. 只处理现有短文本边界内的非空文本；相关长度阈值提取为命名常量并与当前 24 字符行为一致。
3. 两侧规范化文本必须精确相等。
4. 该文本在两侧全文内容索引中都只能出现一次。
5. 两侧来源都必须尚未消费。

满足条件后生成普通的一对一 `ParagraphPair`，相似度为 `1.0`，章节路径选择两侧较具体的路径。标题或其他 paragraph 中存在同文案时，全文唯一性不成立，必须保留原差异。

## 第二层：paragraph 与 section title 角色调和

对仍未匹配的普通、完整、非表格 paragraph，查找对侧规范化文本完全相等的 section title。

候选按以下顺序收窄：

1. 优先使用已经对齐的父 `scope_id`；原始 `section_path` 字符串可以不同。
2. 同一父作用域中的重复标题只有在两侧同文案出现次数相等、序列边界明确且按文档单调顺序能形成唯一一对一映射时才配对。
3. 若没有共同父作用域，只允许两侧全文唯一的精确文本。
4. 多个候选、重复顺序不确定或作用域冲突时不调和。

成功后，paragraph 标记为被对侧标题覆盖，并从单侧新增/删减结果中移除；section title 仅作为只读证据，不合成需要分类的标题 `ParagraphPair`。因此该场景不会产生格式变化，也不会引入“章节标题修改”。

## 第三层：已匹配长段的残余短段覆盖

### 适用形态

以基准侧为例：

```text
基准：A旧（已经与 C 匹配）
      B（相邻且未匹配）
目标：C = A新 + B
```

方向必须对称实现，也要支持目标侧存在未匹配 `B` 的 `1:2` 场景。`B` 可以位于 `C` 的开头、结尾或中间；中间包含不以普通包含关系直接接受，而使用唯一字符跨度和内容守恒校验。

### 候选条件

只有同时满足以下条件才建立残余覆盖：

1. `A旧 <-> C` 已由现有主匹配确认。包含关系不能创建新的主匹配。
2. `B` 是 `A旧` 在同侧文档中的直接相邻未匹配普通 paragraph，并处于兼容父作用域。
3. `B` 是短文本、非空、非表格且不是任何 split unit；本次只消费完整 paragraph。
4. `normalize(B)` 在 `normalize(C)` 中精确出现且只出现一次。
5. 当前主匹配只能得到一个相邻短段覆盖候选；前后同时竞争、多个短段或跨候选争用时不处理。
6. 规范化字符到原始文本的跨度投影完整、连续且可逆验证。

不要求从 `C` 移除 `B` 后的残余文本与 `A旧` 完全相等，因为 `A` 本身允许发生修改。主匹配已经负责确认 `A旧` 与 `C` 的对应关系，残余覆盖只负责证明 `B` 是被长段保留的内容。

### 原始跨度投影

新增内部辅助函数在执行与 `_normalize_match_text` 等价的规则时，同时记录每个规范化字符对应的原始字符范围。它必须：

- 只移除当前规则已经忽略的段首列表标记和空白；
- 保留标点、数字、否定词和义务词；
- 将规范化的唯一 `B` 区间投影回 `C` 的一个连续原始区间；
- 删除该区间后得到保留原始标点和空白的 `C残余`；
- 验证 `normalize(C残余)` 等于从 `normalize(C)` 删除同一区间后的结果；
- 任意映射缺失、非连续或验证失败都拒绝候选。

投影只用于构造分类文本，不修改 DocumentIR 中的 `C`。

### 最终 ParagraphPair

成功覆盖后重写请求内结果：

- 展示侧 paragraph 使用 `A旧 + B` 的合成只读窗口与原始 `C`，让最终差异卡片保留完整上下文；
- `split_unit=True`；
- 新增内部标志 `coverage_reconciled=True`，使分类器能够区分“保留内容覆盖”与普通 split/table 窗口；
- `baseline_match_text`/`target_match_text` 只保存 `A旧` 与 `C残余`；
- `B` 的原单侧结果从最终列表移除；
- section path 继承主匹配中较具体且兼容的路径；
- 相似度沿用主匹配 `A旧 <-> C` 的相似度，不因精确找到 `B` 而提升。

现有分类器优先使用 `baseline_match_text` 和 `target_match_text`，因此只分类 `A旧 -> A新`。分类器在普通 split-unit 格式变化判断之前检查 `coverage_reconciled`：若两侧残余分类文本去空白后相等，直接不报告；不能复用普通 split/table 窗口的“格式变化”分支，否则 `A` 未变化时仍会产生伪格式差异。最终 `DiffItem` 仍展示完整窗口，但不会把 `B` 再次解释为内容新增或删减。

若 `A旧` 与 `C残余` 实际相同，新增的 `coverage_reconciled` 等价分支会使整个窗口不产生差异；若有数值、否定、义务或其他内容变化，则只产生一条对应修改。

## 章节名称变化

内容索引的作用域身份不直接等于 `section_path`，所以已经对齐章节的标题文字变化不会阻断正文调和。但是本次不把 `SectionPair.title_similarity` 直接解释为标题修改，原因是当前章节对齐主要依赖标题字符相似度，重复标题和大幅改名缺少标题之外的独立身份证据。

未来如需新增“章节标题修改”，必须先用父层级、单调邻居和正文覆盖率确认章节身份，并同步扩展 `DiffType`、UI 筛选、颜色、报告和测试。本次不包含该工作。

## 失败保护

以下情况全部保持主匹配原结果：

- 文本为空、过短而不满足既有边界或属于表格；
- 全文唯一性不成立；
- 标题/正文父作用域不兼容或单调顺序不能唯一确定；
- `B` 在 `C` 中出现零次或多次；
- `B` 与 `A` 不相邻；
- 一个主匹配同时存在多个可覆盖短段；
- 来源已被其他窗口消费；
- 规范化字符无法无损投影回连续原始跨度；
- 重写后的消费账本不能证明每个来源最多使用一次。

失败不得抛弃原内容、阻止其他独立候选或修改持久化 IR。

## 实现边界

主要修改集中在 `app/core/diff/semantic_matcher.py`：

- 提取统一的短文本长度常量；
- 建立私有内容索引和消费账本；
- 将当前 `_reconcile_unique_exact_unmatched` 拆分或扩展为有序的内容等价调和流水线；
- 增加带原始跨度的规范化投影；
- 增加 paragraph/title 静默覆盖和残余短段窗口重写。

`ParagraphPair` 增加默认值为 `False` 的内部 `coverage_reconciled` 标志。`diff_classifier.py` 不增加新差异类型，只在普通 split-unit 格式变化判断之前抑制 `coverage_reconciled` 且残余分类文本相同的结果，并验证现有 `_pair_compare_texts` 对残余 `match_text` 的行为。compare graph、service、数据库 schema、报告和 UI 不需要产品接口变化。

## 测试策略

### 现有精确窗口

- `A + B == C` 且同路径时继续由现有精确窗口生成一个 `2:1` 匹配。
- 新调和阶段不重复消费现有窗口来源。
- `1:2` 对称方向保持通过。

### 唯一短文本跨路径

- 两侧全文唯一的相同短文本跨不同 `section_path` 配对。
- 该文本在任一侧其他 paragraph 或 title 中重复时不配对。
- 已匹配重复项也进入唯一性统计。

### paragraph 与 section title

- 一侧 paragraph、另一侧同父作用域 title 时不产生新增、删减或格式变化。
- 重复的 `B）触发条件及执行动作` 只能在父作用域和单调顺序唯一时调和。
- 父作用域冲突或重复候选不唯一时保留原差异。
- 章节名称变化不生成“章节标题修改”。

### 残余短段覆盖

- `A旧 + B` 对 `A新 + B` 只报告 `A旧 -> A新`。
- `B + A旧` 对 `B + A新` 对称处理。
- `B` 位于 `C` 中间时，唯一跨度投影后只分类 `A旧 -> C残余`。
- `A` 未变化时整个组合窗口不产生差异。
- 普通 split/table 窗口原有的格式变化行为不受 `coverage_reconciled` 抑制规则影响。
- `A` 的数字、否定词或义务变化仍由现有规则增强为相应风险。
- `B` 在 `C` 中重复出现、存在两个相邻候选、非相邻或跨不兼容作用域时不覆盖。
- 原始空白、段首列表标记和中英文混排可以投影；标点和数字不得丢失。
- 表格 paragraph 永远不进入残余覆盖。
- baseline/target 两个方向行为对称。

## 验收标准

1. 三类已确认问题均有正向回归测试和至少一个歧义反例。
2. 精确窗口仍优先处理原有 `A+B==C` 场景。
3. `A旧+B` 对 `A新+B` 最多产生一条关于 `A` 的差异。
4. paragraph/title 相同内容不产生任何差异。
5. 章节改名不阻断已对齐作用域内正文调和，但不生成标题修改差异。
6. 所有消费都能证明一对一或一个有界组合窗口，不存在重复消费。
7. 投影失败和候选歧义均保留内容和原差异。
8. 表格匹配、导入规范化、UI 和报告现有行为保持不变。
