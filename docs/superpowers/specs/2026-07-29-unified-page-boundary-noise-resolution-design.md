# 统一页边界噪声识别与短段落上下文设计

## 问题

导入后的 `DocumentIR` 中，页眉页脚可能表现为三种结构：

- 独立的普通 paragraph；
- 独立的 Markdown table paragraph；
- 与真实表格数据行位于同一 paragraph 内的一个或多个 table sentence。

现有普通页眉规则主要依赖完全重复文本。对于只变化页码的复合页眉，例如包含文件名称、文件编号、版本和当前页码的长文本，每页内容并不完全相同，因此不会被删除。表格形式的页眉即使不参与普通段落候选匹配，仍会占据短段落上下文的固定索引和位置分母，导致重复短段落选择错误。

## 目标

1. 使用一套固定候选 LLM 协议判断普通 paragraph、独立 table paragraph 和 table sentence 是否为页面页眉或页脚。
2. 一次调用只能处理一个固定候选，LLM 不能改选上下文中的其他文本。
3. 普通 paragraph 可以整段删除；table sentence 可以逐行删除；混合 table fragment 中的真实数据行必须保留。
4. 删除后的空 paragraph 必须一并移除，不能留下空结构。
5. 普通短段落的上下文和位置计算跳过所有剩余表格单元。
6. 原始 IR 只读，所有删除只应用于规范化副本并记录可审计 trace。
7. 不硬编码文件名称、文件编号、版本、业务字段、固定页码或样例文案。

## 非目标

- 不让 LLM 合并表格或普通段落。
- 不让 LLM 选择任意 paragraph、sentence、行映射或输出新文本。
- 不修改跨页表格的列映射、续行判断、无损投影或候选置信度仲裁规则。
- 不依赖两个版本的文档才能清理页面噪声。
- 不新增独立 implementation plan。

## 统一页边界候选

现有结构修复中的页面噪声阶段重构为统一的 `PageBoundaryNoiseResolver`。它在普通段落合并和表格重建之前运行，使下游 LLM、短段落匹配、QA 和索引都消费相同的清洁副本。

每个物理页分别从页首和页尾向内扫描。每一侧最多检查六个逻辑项，以覆盖多行页眉页脚：

- 普通 paragraph 作为一个候选；
- Markdown table paragraph 按原始 sentence 顺序展开，每个非空内容行作为一个候选；
- Markdown 分隔行不单独交给 LLM，由相邻已删除表头行的结构结果确定是否一并删除。

扫描按页边界向正文方向逐项进行。LLM 返回高置信度删除时继续检查下一项；返回 `keep`、低置信度结果或无效结果时停止当前页的当前方向，避免继续把正文送入 LLM。页首与页尾扫描互相独立，同一候选最多判断一次。

候选的内部来源固定为：

- paragraph：`paragraph_id`；
- table sentence：`paragraph_id + 原始 sentence_index`。

sentence index 仅用于程序内部定位和 trace。LLM 不接收或返回任意行定位字段。`candidate_id` 由算法版本、文档、物理页、边界方向和固定内部来源生成；LLM 只能原样回显该 ID。

## LLM 输入与输出

每次请求只包含：

```json
{
  "candidate_id": "copy-exactly",
  "candidate_text": "固定候选原文",
  "page_no": 11,
  "boundary_side": "page_start",
  "nearby_context": [
    {"relative_position": -1, "text": "..."},
    {"relative_position": 1, "text": "..."}
  ]
}
```

`nearby_context` 继续保留候选前后各最多六项，只用于判断语义和页面位置，不能成为操作目标。输入不包含 `kind`、可由程序推导的结构字段、任意 item ID 列表或列映射。

System prompt 必须详细说明：

- 任务只判断 `candidate_text` 是否为印刷页面页眉或页脚；
- 文件名称、文档编号、版本、保密标记、当前页码等组合可能构成页面元数据，但这些只是通用示例，不是固定词表；
- 真实章节标题、条目标题、正文、注释、业务字段名或列名表头、业务表格数据和跨页续行必须返回 `keep`；排版成表格的印刷页面元数据仍可返回 `remove_as_page_noise`；
- Markdown 表格符号不代表候选一定是页面噪声；
- 上下文只能作为证据，禁止选择、删除、合并或引用上下文项；
- 禁止改写、摘要或补全文本；
- 只能输出一个 JSON object，不得使用 Markdown fence 或附加说明；
- 输出字段、字段类型、动作枚举、置信度范围和失败处理必须完全符合协议。

合法输出严格限定为：

```json
{
  "candidate_id": "copy-exactly",
  "action": "remove_as_page_noise",
  "confidence": 0.96,
  "reason": "该固定候选是位于物理页顶部的印刷文档元数据"
}
```

字段集合必须恰好为 `candidate_id`、`action`、`confidence`、`reason`：

- `candidate_id` 必须与输入完全一致；
- `action` 只能是 `remove_as_page_noise` 或 `keep`；
- `confidence` 必须是 `0.0` 到 `1.0` 的数值，布尔值不合法；
- `reason` 必须是非空字符串；
- 删除动作只有在置信度不低于 `0.90` 时接受；
- 首次格式无效时只重试一次，并在重试 prompt 中列出具体错误和完整格式；
- 超时、异常、第二次格式错误或低置信度删除全部按 `keep` 处理。

## 删除与重放

候选分类逻辑统一，但重放操作按来源粒度执行：

- 普通 paragraph 被确认后，删除整个 paragraph；
- table sentence 被确认后，只删除固定 sentence；
- 同一 paragraph 的多个 sentence 删除在原始索引快照上汇总后一次应用，避免前序删除改变后续索引；
- 如果已删除的 table header 行使相邻 Markdown 分隔行失去所属表头，则规则性地同时删除该分隔行；
- 如果 paragraph 的全部 sentences 均被删除，则删除整个 paragraph；
- 混合 fragment 中未被确认的正文行、表头和数据行逐字符保留；
- `page_no`、保留 paragraph ID 和 sentence 顺序不因局部删除而变化。

结构 trace 需要记录固定候选、内部来源、LLM 决策、置信度、原因以及最终 paragraph 或 sentence 删除操作。内容守恒校验把 trace 明确记录的页面噪声作为唯一允许减少的字符；任一来源定位失败、重复消费、内容守恒失败或结构校验失败时，规范化结果回退为输入副本。

现有确定性规则继续优先处理明确页码、完全重复且位置稳定的页眉页脚、严格图片占位符和确定性标点噪声。只有规则未直接处理的页边界候选才调用 LLM。

## 普通短段落上下文

语义匹配器为普通 paragraph 构造仅包含普通单元的逻辑投影：

- `_ordinary_context_similarity` 的前后两项从普通单元序列获取，不再使用包含表格行的原始偏移；
- 普通短段落的位置相似度使用其在普通单元序列中的序号和普通单元总数；
- 候选仍保存原始 unit index，最终匹配、单调消费、来源 paragraph 和输出顺序不变；
- 表格单元继续由表格匹配和重建逻辑处理，不进入普通段落上下文。

因此，即使某个表格页眉被 LLM 保守保留，它也不会污染普通短段落的邻近上下文或位置分。

## 性能与确定性

- 每次调用只判断一个候选，避免 LLM 在相似候选之间自主换行。
- 同一页首或页尾遇到第一个保留项即停止向内扫描。
- 不同物理页和互不重叠的页首、页尾扫描可使用现有有限并发；同一方向的向内扫描保持顺序。
- 使用现有严格响应缓存和调用统计；缓存键包含模型、system prompt 版本和完整候选 payload。
- Provider 不可用时不执行语义删除，现有确定性规则和普通上下文跳表逻辑仍然生效。

## 测试

### 统一候选与协议

- 普通复合页眉在 `第10页`、`第11页` 文本不同的情况下可由 LLM 分别确认并删除。
- 页首真实正文由 LLM 返回 `keep` 后，当前方向不再继续向内调用。
- 上下文中存在更像页眉的文本时，LLM 仍只能操作固定 `candidate_id`。
- 未知 ID、额外字段、缺失字段、字符串置信度、布尔置信度、非法 action 和低置信度删除均被拒绝。
- 重试 prompt 包含完整字段集合、类型、枚举和固定候选约束。

### 表格粒度删除

- 独立 table paragraph 的全部页眉 rows 被删除后，空 paragraph 一并移除。
- 页眉 rows 与正文 rows 位于同一 table paragraph 时，只删除页眉及失效分隔行，正文 cells 逐字符保留。
- 仅部分 rows 获得有效判断时，未确认 rows 原样保留。
- 多行页眉从页面边缘向内连续删除，遇到第一条真实业务行后停止。
- sentence 删除操作基于原始索引批量应用，不发生索引漂移或错误行删除。

### 短段落与回归

- 只有一侧保留表格页眉时，重复短段落仍按最近普通正文上下文匹配到正确位置。
- 大型业务表格不会改变普通短段落的上下文分和普通序列位置分。
- 表格匹配、跨页续行、列映射、无损投影和差异分类的现有测试保持通过。
- 规范化结果满足内容守恒、唯一来源消费、幂等和原始 IR 不变。
- 运行结构修复、统一规范化、语义匹配、表格重建相关测试及完整测试套件。

## 完成标准

1. 普通 paragraph、独立 table paragraph 和 table sentence 使用同一个固定候选 LLM 协议。
2. LLM 无法选择上下文项或改变固定来源。
3. table sentence 可安全删除，空 paragraph 不残留，混合 fragment 的真实数据不丢失。
4. 所有剩余表格单元不影响普通短段落上下文和位置计算。
5. 原始 IR 保持不变，删除均有 trace，异常时安全回退。
6. 不引入业务文案、固定字段名、列号或页码硬编码。
