# 统一页边界噪声识别与短段落上下文设计

## 问题

导入后的 `DocumentIR` 中，页眉页脚可能表现为独立普通 paragraph、独立 Markdown table paragraph，或与真实表格数据行位于同一 paragraph 内的 table sentence。

现有页面噪声阶段逐行调用 LLM。单行缺少完整表格语境时，模型可能把数字、标准编号、文件名、版本号或 `.docx` 等业务内容误当作页面元数据。一旦模型高置信度返回删除，代码没有第二轮复核。连续多行被判断为噪声时，调用次数还会随行数增加。

表格形式的页眉即使被保守保留，也可能占据普通短段落的上下文索引和位置分母，影响后续匹配。

## 目标

1. 普通 paragraph、独立 table paragraph 和 table sentence 使用同一个页边界批量协议。
2. 每个物理页边界最多调用 LLM 两次：一次初审，必要时一次复审。
3. 每个候选使用请求内临时 ID；LLM 不能遗漏、增加、替换或改选候选。
4. 只有初审与复审都高置信度确认删除的候选才可移除，其他情况一律保留。
5. 删除必须从物理页边缘向正文形成连续区域，不能跨过已保留内容继续删除。
6. 普通 paragraph 可整段删除；table sentence 可逐行删除；混合 table fragment 中的真实数据必须保留。
7. 普通短段落的上下文和位置计算跳过所有表格单元。
8. 原始 IR 只读，所有删除只应用于规范化副本并记录可审计 trace。
9. 不硬编码文件名称、文件编号、版本、业务字段、列号、固定页码或样例文案。

## 非目标

- 不让页面噪声 LLM 合并表格或普通段落。
- 不让 LLM 输出新文本、选择列映射或改变 paragraph/sentence 来源。
- 不修改跨页表格的列映射、续行判断、无损投影或候选仲裁规则。
- 不依赖双文档才能清理页面噪声。
- 不清理正文行首的 `- ` 等 Markdown 噪声。
- 不新增独立 implementation plan。

## 边界批次

一个内部物理页边界由上一页末尾和下一页开头组成。文档开头和文档结尾分别作为外部边界。每个边界侧沿用现有范围，最多收集六个逻辑项，以覆盖多行页眉页脚：

- 普通 paragraph 作为一个逻辑项；
- Markdown table paragraph 按原始 sentence 顺序展开，每个非空且非分隔符的内容行作为一个逻辑项；
- Markdown 分隔行不交给 LLM，由相邻表头行的最终删除结果决定是否一并删除。

上一页末尾和下一页开头都按“从物理边缘向正文”的顺序排列。程序为批次中的候选分配简单临时 ID，例如 `L01`、`L02`。临时 ID 只在当前请求有效，并在程序内部一一映射到：

- paragraph：`paragraph_id`；
- table sentence：`paragraph_id + 原始 sentence_index`。

内部来源不发送给 LLM，也不写回文档。同一候选只属于一个固定边界侧，避免在相邻批次中重复判断。

## 两轮 LLM 协议

### 初审输入

```json
{
  "boundary_id": "copy-exactly",
  "items": [
    {"id": "L01", "position": "previous_page_end", "text": "..."},
    {"id": "L02", "position": "next_page_start", "text": "..."}
  ]
}
```

每个候选文本只出现一次。输入不包含 `kind`、paragraph ID、sentence index、精确页码、列映射或其他可由程序推导的结构数据。`position` 只允许：

- `previous_page_end`
- `next_page_start`
- `document_start`
- `document_end`

数组顺序表达同一侧候选距物理边缘的相对距离。

### 初审输出

```json
{
  "boundary_id": "copy-exactly",
  "labels": [
    {
      "id": "L01",
      "action": "remove_as_page_noise",
      "confidence": 0.96,
      "reason": "该项是位于物理页边缘的重复印刷元数据"
    },
    {
      "id": "L02",
      "action": "keep",
      "confidence": 0.99,
      "reason": "该项具有序号、要求描述和性能指标，是业务数据行"
    }
  ]
}
```

### 复审

如果初审没有任何有效删除候选，当前边界只调用一次。若初审存在有效删除候选，第二次请求包含相同的 `boundary_id`、原始 `items` 和完整初审标签。复审负责发现误删风险，但不能改变候选集合。

复审使用与初审相同的输出结构。最终删除要求同一 ID 在两轮中都返回有效的 `remove_as_page_noise`；任一轮返回 `keep`、低置信度或无效结果时，最终结果均为 `keep`。

## 严格格式校验

System prompt 必须完整描述输入、输出和失败处理。程序同时执行以下校验：

- 顶层字段必须恰好为 `boundary_id`、`labels`；
- `boundary_id` 必须与输入完全一致；
- `labels` 必须与输入 ID 集合和顺序完全一致，不能缺失、重复、重排或包含未知 ID；
- 每个标签字段必须恰好为 `id`、`action`、`confidence`、`reason`；
- `action` 只能是 `remove_as_page_noise` 或 `keep`；
- `confidence` 必须是 `0.0` 到 `1.0` 的 JSON 数值，布尔值和字符串不合法；
- `reason` 必须是非空且不超过长度上限的字符串；
- 单轮删除标签只有在置信度不低于 `0.90` 时有效。

协议错误不触发第三次调用。任一轮出现超时、异常、非法 JSON、字段错误、ID 集合错误或无法可靠建立映射时，整个批次安全保留。单个合法标签的低置信度删除只降级该候选为保留。

## Prompt 判断原则

Prompt 不再把数字或文件编号当作页面噪声的正向捷径，而是关系性地定义页眉页脚：它们是依赖物理页边界位置、与正文逻辑结构无关，并通常具有跨页重复模式的印刷附属信息。

Prompt 必须明确：

- 数字、序号、标准号、文件名、版本号、扩展名和页码样式文本本身都不足以证明候选是页面噪声；
- 具有序号或键值列，并包含要求描述、性能指标、标准引用或附件名称的行，是强业务内容形态；
- 业务行即使包含 `.docx`、Markdown 管道符、HTML `<br>`、空单元格或手工换行，也必须返回 `keep`；
- 真实章节标题、条目标题、正文、注释、列名表头、业务表格数据和跨页续行必须保留；
- 排版成表格的重复印刷页面元数据仍可删除，但必须结合整个边界批次的内容角色、相对位置和重复模式判断；
- 无法确定时默认 `keep`；误保留页面噪声优于误删正文；
- 禁止改写、摘要、补全、合并或生成文档文本；
- 只能输出一个裸 JSON object，不得附加 Markdown fence 或说明文字。

## 删除与重放

两轮结果合并后，程序分别对每个边界侧应用连续性约束：从物理边缘开始，只有连续的最终删除项可以移除；遇到第一个最终保留项后，该侧更靠正文的所有候选强制保留。

重放按来源粒度执行：

- 普通 paragraph 被确认后删除整个 paragraph；
- table sentence 被确认后只删除固定 sentence；
- 同一 paragraph 的多个 sentence 删除在原始索引快照上汇总后一次应用，避免索引漂移；
- 已删除 table header 行使紧邻 Markdown 分隔行失去所属表头时，规则性地一并删除分隔行；
- paragraph 的全部 sentences 均被删除后，删除空 paragraph；
- 混合 fragment 中未被确认的正文行、表头和数据行逐字符保留；
- `page_no`、保留 paragraph ID 和 sentence 顺序不因局部删除而变化。

Trace 记录批次 ID、请求内候选 ID、内部来源、两轮标签、最终动作以及 paragraph/sentence 删除操作。内容守恒校验仅允许减少 trace 明确记录的页面噪声。来源定位失败、重复消费、内容守恒失败或结构校验失败时，规范化结果回退为输入副本。

现有确定性规则继续优先处理明确页码、完全重复且位置稳定的页眉页脚、严格图片占位符和确定性标点噪声。只有规则未处理的页边界候选进入批量 LLM 协议。

## 普通短段落上下文

语义匹配器为普通 paragraph 构造仅包含普通单元的逻辑投影：

- 邻近上下文从普通单元序列获取，不使用包含表格行的原始偏移；
- 普通短段落的位置相似度使用其在普通单元序列中的序号和普通单元总数；
- 候选仍保存原始 unit index，最终匹配、单调消费、来源 paragraph 和输出顺序不变；
- 表格单元继续由表格匹配和重建逻辑处理。

因此，即使表格页眉被保守保留，也不会污染普通短段落的邻近上下文或位置分。

## 性能与确定性

- 每个边界第一次调用批量判断全部候选，存在有效删除候选时最多再调用一次复审；
- 不为格式错误重试，严格保证每个边界最多两次 LLM 调用；
- 两轮都使用完整固定 ID 集合和严格响应校验；
- 不同物理页边界可使用现有有限并发；同一边界的初审和复审顺序执行；
- 使用现有响应缓存和调用统计，缓存键包含模型、system prompt 版本、审查阶段和完整 payload；
- Provider 不可用时不执行语义删除，确定性规则和普通上下文跳表逻辑继续生效。

## 测试

### 批量协议与调用上限

- 同一边界的两侧候选在一个请求中全部获得标签；连续六个候选不再触发六次调用。
- 初审全部保留时只调用一次；存在删除候选时恰好调用两次；任何路径均不超过两次。
- 两轮一致删除才生效；任一轮保留、低置信度或无效时保留原文。
- 未知 ID、额外 ID、重复 ID、顺序变化、额外字段、缺失字段、非法置信度和非法 action 均导致安全保留。
- 模型不能用边界中的另一个候选替换固定 ID；完整集合校验失败时整个批次保留。

### 正文防误删

- 带序号、要求描述、指标、标准引用或附件文件名的业务表格行保留。
- 包含数字、文件编号、`.docx`、`<br>`、换行或 Markdown 表格符号的业务内容不能仅凭这些特征删除。
- 初审误删而复审保留时正文不被删除。
- 两轮都误删更内部的候选，但其外侧已有保留项时，连续性约束仍保留该候选。

### 表格粒度删除

- 独立 table paragraph 的全部页眉 rows 经两轮确认删除后，空 paragraph 一并移除。
- 页眉 rows 与正文 rows 位于同一 table paragraph 时，只删除连续页眉及失效分隔行。
- 仅部分 rows 获得有效双重确认时，未确认 rows 原样保留。
- sentence 删除基于原始索引批量应用，不发生索引漂移。

### 回归

- 普通复合页眉在当前页码变化时仍可由两轮确认并删除。
- 只有一侧保留表格页眉时，重复短段落仍按最近普通正文上下文匹配。
- 表格匹配、跨页续行、列映射、无损投影和差异分类现有测试保持通过。
- 规范化结果满足内容守恒、唯一来源消费、幂等、`page_no` 保留和原始 IR 不变。
- 运行结构修复、统一规范化、语义匹配、表格重建相关测试及完整测试套件。

## 完成标准

1. 三种页边界文本来源使用同一个边界批量协议。
2. 每个边界最多两次 LLM 调用。
3. 只有两轮完整、合法且一致的高置信度删除才会改变规范化副本。
4. 临时 ID 与内部来源严格映射，LLM 无法遗漏、增加或替换操作目标。
5. 删除满足边缘连续性，table sentence 可安全移除且混合 fragment 的业务数据不丢失。
6. 所有表格单元不影响普通短段落上下文和位置计算。
7. 原始 IR 保持不变，`page_no` 保留，删除有 trace，异常时安全回退。
8. 不引入业务文案、固定字段名、列号或页码硬编码。
