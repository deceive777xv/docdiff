# 跨页表格续行与章节窗口匹配修复设计

日期：2026-07-24

## 背景

两份复杂测试文档暴露出两个相互独立的问题：

1. 清洗后的 IR 已移除页脚，但跨页表格续行仍未形成最终合并操作。以目标文档中的 `0.1。` 为例，规则层能够生成候选，并给出 `blank_key_cells`、`next_row_restores_key_pattern`、`boundary_artifacts_only` 和 `cross_version_support` 四项正向证据，但当前 LLM 协议要求同时返回 `row_action=merge` 与 `table_action=merge_fragments`。任一字段不符合、置信度不足或响应格式无效，候选都会静默保留为分离状态。
2. 相同正文可能因解析结果不同而属于不同章节，或被切成不同数量的段落。样例中，基准文档把正文放入 `1.1.28 附件功能 / 失效保护` 子章节，目标文档仍把它放在 `1.1.28 附件功能` 中。当前章节对齐只比较标题，且忽略 `Section.level`，导致子章节在进入段落匹配前就被判为整节删除。

## 目标

- 让 LLM 只判断“候选行是否属于同一逻辑行”，程序自动派生安全的重构操作。
- 支持跨页片段具有不同物理列数、不同空列位置和更宽的页眉表格。
- 不允许在列映射不明确时丢弃或错放非空业务内容。
- 在不修改持久化 DocumentIR 章节结构的前提下，匹配父章节与相邻子章节中的同源正文。
- 支持由解析差异导致的 `1↔2`、`2↔1` 及小范围相邻段落窗口匹配。
- 保持匹配单调、内容不重复消费，并对所有拒绝路径提供可审计原因。

## 非目标

- 不把整个文档或整张表直接交给 LLM 重写。
- 不要求两个跨页表格片段具有相同物理列数。
- 不进行无边界的全局跨章节语义搜索。
- 本设计暂不改变“LLM 判断无实际差异的项目是否展示”的分类协议；该项需单独确认“完全一致”和“仅格式变化”的展示边界。

## 设计一：跨页表格的原子 LLM 判定

### 处理流程

1. 根据相邻物理页定位前页末尾和后页开头的表格片段。
2. 将重复页眉、页脚、分隔行和文档元数据标记为边界内容，不用它们决定正文列数。
3. 从前页完整正文行、后页下一条完整正文行以及另一版本对应表格中推断规范逻辑列。
4. 生成最多三个按物理顺序单调的列映射候选。
5. 过滤会造成非空关键列冲突、非空业务单元格无法投影或内容丢失的映射。
6. 把剩余映射作为带稳定 `mapping_id` 的有限候选交给 LLM。
7. LLM 返回 `merge_row` 或 `keep`；存在多个映射时只能选择提供的 `mapping_id`。
8. 接受 `merge_row` 后，程序自动生成列投影、行合并和跨段落片段合并操作。

### 物理列与逻辑列

物理列是 PyMuPDF4LLM 在某一行实际输出的管道分隔位置。逻辑列是“序号、项目、要求、备注”等业务角色。物理列数变化不代表逻辑表结构变化。

规范逻辑宽度由正文上下文确定，不再由当前片段的最大物理列索引或页眉宽度确定。允许以下输入投影到同一个四列逻辑表：

```text
前页正文：6 个物理列
后页页眉：9 个物理列
后页续行：8 个物理列
逻辑正文：4 个逻辑列
```

页眉、页脚或纯装饰列可以不映射；任何非空业务内容都必须映射到唯一逻辑列。

### 硬性条件

- 已知页码时，候选位于相邻物理页。
- 至少存在一个顺序单调且无关键列内容冲突的映射。
- 候选续行中的全部非空业务内容均能安全投影。
- 合并和投影操作能够通过现有重放验证。

### 评分证据

以下条件只参与候选排序和 LLM 上下文，不要求全部满足：

- 逻辑关键列为空。
- 下一条完整行恢复序号或关键列类型。
- 另一版本存在对应完整行。
- 前后正文列型相似。
- 两行之间仅存在页眉、页脚或分隔内容。

### LLM 响应

响应采用单一原子动作，不再暴露独立的 `table_action`：

```json
{
  "boundary_id": "stable-boundary-id",
  "candidate_id": "stable-candidate-id",
  "action": "merge_row",
  "mapping_id": "mapping-1",
  "confidence": 0.93,
  "roles": {
    "previous_row": "body_row",
    "continuation_row": "continuation_row"
  },
  "reason": "后页首行关键列为空且内容续接前页要求列"
}
```

响应格式无效时允许一次带校验错误信息的格式纠正重试。第二次仍无效则保持分离，不做推测性合并。

### 操作派生

LLM 只决定行关系和有限映射候选。接受后由程序派生：

- `project_columns`
- `merge_rows`
- 当源行来自不同段落时的 `merge_fragments`

因此 LLM 不需要理解重放操作之间的依赖，也不会因为把“合并行”和“合并片段”视为两个不同业务判断而拒绝正确续行。

### Trace

每个物理页边界记录候选生成和最终状态：

- `no_table_candidate`
- `no_safe_mapping`
- `ambiguous_column_mapping`
- `llm_invalid_response`
- `llm_keep`
- `low_confidence`
- `merged`

Trace 同时保存候选映射、被拒绝映射的原因、LLM 原子判断和生成的操作 ID。

## 设计二：逻辑章节组与相邻段落窗口

### 逻辑章节组

DocumentIR 保持原有扁平章节列表和 `level`，对比阶段临时构造逻辑章节组：

```text
1.1.28 附件功能
├── 本章节段落
└── 失效保护
```

章节组由一个已经对齐的编号章节，以及其后连续的、更深层级章节组成。若某个子章节只在一侧存在，但其最近的低层级祖先已经与另一侧对齐，则该子章节不立即作为整节新增或删除，而是加入祖先章节的段落匹配范围。

逻辑章节组只影响对比范围，不合并、移动或改写持久化 IR。差异项仍保留最具体的来源章节路径。

### 段落匹配阶段

每个逻辑章节组按以下顺序处理：

1. 规范化文本完全一致的唯一段落作为锚点。
2. 使用完整文本 embedding、词法相似度和上下文完成现有 `1↔1` 匹配。
3. 对仍未匹配的连续段落生成有界窗口：
   - `1↔2`
   - `2↔1`
   - `2↔2`
   - 必要时最多 `3↔3`
4. 对窗口拼接文本计算规范化相等、embedding 相似度和前后文一致性。
5. 只把得分接近或存在重复短文本的冲突簇交给 LLM 重排。
6. 使用单调选择保证顺序不回退，且每个源段落最多被一个匹配窗口消费。

### 安全边界

- 窗口不能跨出同一逻辑章节组。
- 只能组合连续段落。
- 每侧窗口最多三个段落，并设置总字符上限。
- 短文本或重复文本必须结合前后最多两项上下文。
- 存在多个近似候选且 LLM 无法给出高置信度选择时，保留为未匹配。
- 不使用 LLM 截断文本替代 embedding；embedding 始终接收完整匹配文本。

## 数据流

```text
导入后的规范 IR
  → 标题章节对齐
  → 跨页表格候选与映射假设
  → LLM 原子续行判断
  → 重放表格操作
  → 重新章节对齐
  → 构造逻辑章节组
  → 1↔1 段落匹配
  → 有界相邻窗口匹配
  → 差异分类
```

## 验收标准

### 跨页表格

- 两份测试 JSON 中，目标文档的 `0.1。` 合并到序号 33 的“异响”行。
- 页眉物理列数大于正文列数时仍能生成安全映射。
- 前后页正文物理列数不同但逻辑角色一致时能够合并。
- 非空业务单元格存在多个可能目标列时不自动合并，并记录 `ambiguous_column_mapping`。
- LLM 返回 `merge_row` 后自动生成行合并和片段合并操作。
- 无效 LLM 响应只重试一次，失败后保留原文且 Trace 可解释。

### 段落匹配

- 样例中的 `1.1.28 附件功能 / 失效保护` 与另一侧 `1.1.28 附件功能` 进入同一匹配范围。
- 图示“应急模式”段落不再同时产生错误新增和错误删减。
- 一侧一段、另一侧两段的“故障信息查询”内容能够形成一个匹配窗口。
- 多个完全相同的短段落仍按上下文和顺序稳定匹配。
- 相邻但不属于同一逻辑父章节的内容不能组成窗口。

## 测试策略

- 为不同物理列数、稀疏续行、多映射歧义和非空内容守恒增加表格单元测试。
- 为 LLM 单一动作、映射选择、格式重试和 Trace 状态增加协议测试。
- 为父子章节分裂、`1↔2` 段落切分、重复短文本和单调消费增加语义匹配测试。
- 使用两份现有 JSON 运行回归分析，核对已知跨页行和“失效保护”区域。
- 完成后运行完整 pytest，并检查内容守恒及重放幂等性。
