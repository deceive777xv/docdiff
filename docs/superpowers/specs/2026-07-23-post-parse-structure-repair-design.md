# 导入时解析后结构修复设计

## 背景

分页感知解析、跨页表格裁决和上下文段落匹配已经解决了重复解析、候选级结构冲突以及大量重复短文本的局部消歧问题，但两份复杂样本仍暴露出更早阶段的结构偏差：

- Markdown 标题识别不稳定，正文可能被误建为章节，真实章节也可能留在普通段落中；
- 相同的 `A）/B）` 等结构标题反复出现，容易成为错误的顶级章节；
- 同一语义内容在两个版本中可能被切成 `1:N` 或 `N:1` 个段落；
- `附表`、`失效保护` 等无编号标题的层级和归属不明确；
- 单份文档内的跨页表格片段可能存在明显但尚未修复的结构关系。

这些问题会同时影响结构化展示、QA 分块、索引以及后续对比。仅在匹配阶段增加容错不能纠正已经错误的章节路径，也无法阻止结构噪声进入展示和检索。

## 目标

1. 在新文档导入时保存不可变的原始 `DocumentIR`，并生成默认使用的规范化 `DocumentIR`。
2. 使用严格确定性规则修复高置信度结构问题，将不确定判断交给受限的局部 LLM。
3. 保证修复只调整结构和组合关系，不生成、改写或概括正文。
4. 让结构化展示、QA、索引和文档对比统一消费规范化结果。
5. 将单文档固有修复与双版本对比时的表格重建分开，避免对比结论污染导入结果。
6. 出现异常时安全回退，不让结构修复导致导入失败。

## 非目标

- 本阶段不提供旧 JSON 的迁移、重新规范化接口或 UI。
- 用户提供的两份 JSON 只作为测试夹具，不作为正式 legacy 导入格式。
- 不从旧 normalized 结果递归生成新 normalized 结果。
- 不引入 OCR、版面视觉模型或新的 PDF 解析器。
- 不让 LLM 创建新文本、修改字符、重新排序任意正文或访问整篇文档。
- 不改变现有差异结果格式和比较页面交互。

## 方案选择

### 方案 A：仅在对比阶段修复

实现最小，但展示、QA 和索引继续消费错误结构，同一文档在不同功能中可能呈现不同层级，因此不采用。

### 方案 B：导入时直接覆盖原始解析结果

下游使用简单，但无法审计、回滚或用新算法重新生成结果，错误修复还可能永久覆盖证据，因此不采用。

### 方案 C：保存 raw 与 normalized 双份结果（采用）

导入先保存不可变 raw，再在副本上执行结构修复并保存 normalized。现有下游默认读取 normalized，trace 保存全部操作和拒绝原因。该方案兼顾下游一致性、可审计性和安全回退。

## 总体数据流

```text
PDF
  -> PyMuPDF4LLM
  -> raw_ir
  -> parsed/raw/{doc_id}.json
  -> StructureRepairPipeline
       1. 噪声识别
       2. 标题与章节层级规范化
       3. 错位段落重新归属
       4. 1:N / N:1 文本片段合并
       5. 高置信度单文档表格修复
       6. 有界局部 LLM 裁决
  -> normalized_ir
  -> parsed/{doc_id}.json
  -> 结构化展示 / chunks / index / QA / compare
```

结构修复 trace 保存到：

```text
parsed/traces/{doc_id}.structure.json
```

现有数据库字段 `parsed_json_path` 继续指向 `parsed/{doc_id}.json`，即 normalized 结果。raw 和 trace 路径由 `doc_id` 派生，不增加数据库字段。

对比阶段仍可在两份 normalized IR 的工作副本上执行跨版本表格重建。其操作写入独立的对比 trace，不回写任一文档的导入结果。

## StructureRepairPipeline

### 输入与输出

```python
repair(document: DocumentIR, context: RepairContext) -> StructureRepairResult
```

`StructureRepairResult` 包含：

- `document`：规范化后的深拷贝；
- `trace`：已执行、拒绝和回退的操作；
- `status`：`repaired`、`unchanged` 或 `fallback`；
- `warnings`：非致命异常和安全拒绝原因。

管线不得修改调用者传入的 `DocumentIR`。同一版本算法重复处理 normalized IR 时必须保持幂等。

### 处理顺序

1. 识别可安全移除的重复页面噪声；
2. 规范 Markdown 标题文本和显式编号层级；
3. 处理重复通用结构标题并修正章节归属；
4. 识别严格连续的普通段落片段；
5. 处理单文档内结构证据完整的表格片段；
6. 把剩余有限歧义组成局部候选窗口交给 LLM；
7. 对全部候选执行内容守恒、来源 ID、顺序和幂等预检；
8. 生成 normalized IR 和完整 trace。

后一步只能消费前一步已经确定的结构，不得覆盖已经执行且不兼容的操作。

## 严格确定性规则

确定性规则只处理不依赖业务语义且证据充分的情况。

### 标题规范化

- 去除标题外围的 Markdown 强调标记并规范空白，例如 `**3.1**` 规范为 `3.1`；
- 只有独立、较短、无句末标点、编号格式严格且局部层级顺序兼容的段落才能自动提升为章节；
- 显式编号决定基础层级，不能仅因字体或短文本提升标题；
- 重复的 `A）/B）` 等通用结构标题只能成为当前编号章节内部结构，不能自动成为跨编号章节的顶级同级节点；
- 保持当前扁平 `Section` 列表，通过修复 `Section.level` 表达层级。下游使用 level 栈构造 `1.1.18 > 附表……` 形式的章节路径。

### 页面噪声

只有以下项目可以自动从 normalized IR 移除：

- 在多个页面相同位置重复且文本稳定的页眉或页脚；
- 纯数字页码或严格的“第 N 页”；
- 重复稳定的文件名、文件编号、版本信息；
- 已明确忽略的图片占位符；
- 仅含孤立标点且相邻正文能够证明其为切分残片的项目。

其他短文本一律保留。移除仅发生在 normalized 副本中，原始内容和来源位置完整保存在 raw 与 trace。

### 普通段落片段

只有同时满足下列条件才自动合并：

- 两段在来源顺序上相邻；
- 前段没有句末终止标点；
- 后段不具备标题特征；
- 两段连接后在空白、标点或枚举结构上具有明确连续性；
- 合并不会跨越显式章节、表格或页面稳定噪声边界。

不满足全部条件的 `1:N` 或 `N:1` 候选进入 LLM 裁决，不能仅依赖相似度自动合并。

### 单文档表格修复

自动合并表格片段必须同时满足：

- 来源相邻，或位于相邻物理页的分页交界；
- 列映射完整、单调且覆盖所有保留的非空单元格；
- 关键列不存在两个非空且互相冲突的值；
- 页眉、页脚和表头候选已有明确分类；
- 操作可重放且再次执行不会产生变化。

任一条件不满足就保留原结构，等待对比阶段利用双版本上下文裁决。`key column conflict at logical column 0` 属于候选级安全拒绝，不得升级为导入或对比任务级异常。

## 有界局部 LLM 裁决

LLM 只处理规则无法安全决定的候选：

- 编号上下文不完整的疑似遗漏标题；
- 疑似错误章节的降级和段落重新归属；
- `1:N` 或 `N:1` 段落组合；
- 语义连续但结构证据不足的表格片段；
- `附表`、`失效保护` 等无编号标题的层级和归属。

允许动作固定为：

```text
keep
promote_to_section
demote_to_paragraph
move_to_section
merge_paragraphs
remove_noise
merge_table_fragments
```

每次请求只包含候选前后有限窗口、稳定来源 ID、当前位置和结构提示。LLM：

- 只能引用请求中已有 ID；
- 不能生成、重写、摘要或补全文本；
- 不能执行窗口外操作；
- 不能返回任意列映射或任意新顺序；
- 置信度必须达到 `0.85`。

响应存在未知 ID、来源顺序冲突、内容丢失、非法动作、低置信度或 schema 错误时，当前候选保持原样。Provider 不可用、超时或异常时同样安全回退。

## 内容守恒与稳定标识

normalized IR 必须满足：

1. 除 trace 明确记录的噪声外，所有 raw 文本字符均保留；
2. 合并只能是已有来源文本的确定性拼接，不得改写字符；
3. 移动和层级调整不得改变来源项内部文本；
4. 未合并项目尽量保留原 ID；
5. 合并项目使用确定性派生 ID，并在 trace 中保存全部 source IDs；
6. 任一来源项最多被一个消耗型操作占用；
7. normalized IR 再次运行同版本修复算法不得产生新的操作。

内容守恒校验失败时放弃整份修复结果，回退到 raw IR。

## 持久化和失败处理

导入持久化顺序：

1. 将 raw IR 写入临时文件并原子替换到 `parsed/raw/{doc_id}.json`；
2. 在 raw 的深拷贝上执行结构修复；
3. 校验内容守恒、稳定 ID 和幂等性；
4. 将 normalized IR 与 structure trace 分别写入临时文件；
5. 原子替换目标文件后，再更新数据库状态并生成 chunks/index。

trace 至少记录：

- schema 和算法版本；
- 文档 ID、raw hash 与 normalized hash；
- 每个操作的类型、输入 IDs、输出 ID 和理由；
- LLM 判断、置信度及原始候选引用；
- 被安全拒绝的候选和冲突码；
- 回退阶段、异常类型和失败原因。

任何规则或 LLM 步骤异常都不应使导入失败。若整份修复无法通过校验：

- `normalized_ir = raw_ir`；
- 写入 `fallback` trace；
- 继续后续存储、分块和索引。

只有 raw IR 本身无法持久化或后续已有的关键存储步骤失败时，导入任务才失败。

## 下游读取约定

- 结构化展示默认读取 normalized JSON；
- QA 分块和索引只使用 normalized IR 的章节路径与正文；
- 页面噪声不进入 chunks，也不参与对比；
- 对比服务读取 normalized IR 后创建工作副本；
- 跨版本表格重建和匹配不得修改已保存 normalized JSON；
- compare-specific trace 与 structure trace 分开保存和校验。

## 兼容性与范围

本功能只作用于实现上线后的新导入：

- 不扫描、迁移或静默改写已有 parsed JSON；
- 不新增 legacy JSON 导入或“重新规范化”命令；
- 不修改数据库 schema；
- 两份用户样本可直接作为测试中的 raw fixture 运行 repair，但不形成产品接口；
- 算法升级期间，测试环境可重新导入 PDF 或重新运行 fixture，生产级迁移不在本阶段范围内。

## 测试策略

### 单元测试

- 标题强调标记与空白规范化；
- 严格编号标题提升及不合法标题拒绝；
- 重复 `A）/B）` 保持在编号章节内部；
- 页眉、页脚、页码和图片占位符识别；
- 非噪声短文本不会被删除；
- 明确连续片段合并与模糊片段拒绝；
- 完整单调列映射合并；
- 关键列冲突局部拒绝；
- 所有操作的来源占用和稳定派生 ID；
- 内容守恒与同版本幂等。

### LLM 与失败测试

- 合法的提升、降级、移动、段落合并和表格合并；
- 低置信度、未知 ID、重复 ID、非法动作和 schema 错误；
- 内容改写、顺序冲突和窗口外引用必须被拒绝；
- Provider 缺失、超时和异常回退；
- 局部候选失败不影响其他候选；
- 整体守恒失败时 normalized 回退为 raw，并写入 fallback trace。

### 导入与下游集成

- raw、normalized 和 trace 均按约定路径原子写入；
- `parsed_json_path` 指向 normalized；
- 展示、chunks、index、QA 和 compare 使用同一 normalized 结构；
- 明显噪声不进入索引和差异结果；
- compare-time 表格修复不回写 normalized；
- 导入修复失败不导致任务失败；
- raw 持久化失败仍按关键错误处理。

### 两份复杂样本验收

- 重复 `A）/B）` 不再错误形成顶级章节；
- `1.1.4` 等已知章节归属得到纠正；
- 页眉、页脚和图片占位噪声不进入展示、QA 或差异结果；
- “三年/10 万公里 → 六年/15 万公里”“510W → 10W”等真实修改仍被识别；
- “另一文档中实际存在相同规范化内容但仍 unmatched”的项目由约 170 项降至 20 项以内；
- 已确认的明显噪声差异由约 76 项降至 0；
- 如果未达到量化目标，报告剩余类别，不通过放宽安全规则、删除正文或隐藏差异达标；
- 全流程不再因 `key column conflict at logical column 0` 等候选冲突抛出任务级异常。

## 完成标准

1. 新导入同时保存不可变 raw、默认 normalized 和可审计 trace。
2. 除明确噪声外，修复前后正文字符守恒。
3. 规则只自动处理高置信度情形，歧义候选由受限局部 LLM 裁决。
4. LLM 无法改写文本，任何无效输出均保持原结构。
5. 展示、QA、索引和对比统一使用 normalized IR。
6. 单文档修复与双版本表格重建互不回写。
7. 修复幂等，异常时 normalized 安全回退到 raw。
8. 现有完整测试继续通过，并满足复杂样本的结构和量化验收要求。
