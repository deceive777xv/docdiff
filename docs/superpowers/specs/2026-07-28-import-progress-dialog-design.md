# 文档导入汇总进度弹窗设计

## 目标

统一规范化增加了段落与跨页表格的 LLM 判断，导入耗时会明显增长。文档库需要在不改变导入结果和并发模型的前提下，持续告知用户当前阶段、批次完成度和失败情况。

## 交互设计

- 用户一次选择一个或多个文件后，只创建一个批次进度弹窗。
- 弹窗为非阻塞窗口，显示总体进度条、`已完成 X/Y`、当前活动文件及其阶段。
- 多文件保持现有并发导入行为，总体进度为批次内各文件阶段进度的平均值。
- 关闭弹窗只隐藏窗口，不中断后台任务；本次不提供取消按钮，因为解析、LLM 和索引调用目前没有安全的协作式取消边界。
- 批次运行期间禁用“导入文档”“新增版本”和“删除”，批次结束后恢复，避免新增版本入库与文档级联删除竞态。
- 批次结束时只显示一次结果汇总：全部成功时显示成功数量；存在失败时同时列出成功数量、失败数量和失败文件。
- 完成后刷新文档库一次，不再为每个文件分别弹出成功消息。

## 进度模型

进度由 `_IngestWorker` 根据 LangGraph 节点完成事件上报，不伪造逐 token 或逐候选进度：

| 阶段 | 文件进度 | 展示文案 |
| --- | ---: | --- |
| 开始 | 0% | 准备导入 |
| 文件检查完成 | 10% | 正在解析文档 |
| 解析完成 | 35% | 正在规范化段落与跨页表格 |
| 规范化、入库完成 | 85% | 正在构建检索索引 |
| 全部节点完成 | 100% | 导入完成 |

规范化阶段可能包含多个 LLM 请求，因此进度条可能在 35% 到 85% 之间停留一段时间。弹窗通过阶段文案说明真实状态，不使用虚假匀速动画。

## 组件边界

### `_IngestWorker`

- 新增 `progress(file_path, percent, stage)` 信号。
- 使用 `ingest_graph.stream()` 获取节点完成事件，并从事件中的 `status` 推导下一阶段。
- 保留现有 `refresh_needed`、`finished` 和 `error` 语义；异常仍由单个 worker 隔离。

### `_ImportProgressDialog`

- 只负责展示批次快照，不访问数据库或控制线程。
- 接收每个文件的进度、阶段和最终状态，计算总体平均进度。
- 用户关闭时隐藏；批次管理器仍持有对象，后续进度更新不丢失。

### `LibraryPage`

- 将文件选择结果作为一个批次启动，并维护文件到 worker/thread 的关联状态。
- 汇总成功和失败；所有 worker 结束后刷新一次、恢复按钮并显示单个结果消息。
- 新增版本复用同一批次机制；一个批次中的所有文件使用同一个 `document_id`。

## 错误与生命周期

- 单个文件失败不停止同批次其他文件。
- worker 必须无论成功或失败都退出对应线程。
- 线程完成后继续执行现有 `deleteLater` 和 `_threads.discard` 清理。
- 弹窗隐藏或所属页面暂时不可见时，后台导入继续运行。
- 批次结束后弹窗自动关闭；结果消息成为最终状态入口。

## 测试

- worker 将 LangGraph 状态映射为单调递增的阶段进度。
- 多文件进度按平均值汇总，完成计数正确。
- 关闭弹窗不调用线程终止或 worker 取消。
- 同一批次只创建一个弹窗，并在完成前禁用导入相关按钮。
- 部分失败时其他文件继续，最终只显示一个汇总消息。
- 旧有线程信号连接、线程清理、版本展示和数据库刷新测试继续通过。

## 非目标

- 不实现 LLM token、候选数量或向量条目的精确进度。
- 不实现暂停、取消或强制终止。
- 不改变导入节点、统一规范化算法、并发数量或数据库事务边界。
